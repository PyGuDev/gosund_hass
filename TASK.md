# Задача: локальное управление розеткой EP8

## Цель

Извлечь текущие `device_id` и `local_key` умной розетки EP8 из приложения
GHome без сброса или повторной привязки устройства. Затем расшифровать сетевой
захват Tuya LAN 3.3, определить используемые Data Points (DPS) и подготовить
параметры для локального управления розеткой.

## Исходные данные

- PCAP: локальный захват PCAPdroid (путь не коммитить; см. `.secrets/` / операторский каталог)
- Рабочий каталог: корень этого репозитория
- Android-приложение: GHome 5.8.5
- Package name: `com.gosund.smart`
- Розетка в GHome: `EP8`

Идентификаторы устройства, LAN IP, MAC и `local_key` хранятся только в
`.secrets/ep8.env` (gitignored). Не публиковать их в docs, тестах или скриптах.

## Уже установлено

- Устройство использует экосистему Tuya.
- Локальный протокол: Tuya LAN 3.3.
- Локальный порт управления: `6668/TCP`.
- Формат пакетов: `0x55AA`, CRC32, AES-128-ECB.
- В PCAP обнаружены два успешных `CONTROL_NEW` (`0x0d`) и ответы устройства.
- Все проверенные CRC32 корректны.

## Созданные материалы

- `REVERSE_ENGINEERING.md` — результаты анализа протокола и трафика.
- `analyze_tuya_pcap.py` — извлечение кадров, проверка CRC и расшифровка при
  наличии `local_key`.

## Текущий блокирующий секрет

Для расшифровки нужен уникальный 16-байтовый `local_key`. Он не передаётся
открытым текстом в PCAP и не может быть практически восстановлен из AES-пар.

## Проверенные способы извлечения

- `run-as com.gosund.smart` недоступен: приложение не `debuggable`.
- `android:allowBackup="false"` — штатный backup приватной базы запрещён.
- `am dumpheap` отклонён: процесс не `debuggable`.
- Root на физическом телефоне отсутствует (`su` не установлен).
- В журналах GHome ключ и объект устройства не выводятся.
- WebView DevTools socket для GHome отсутствует.
- Внешний кэш GHome доступен, но содержит только ресурсы мини-приложений.
- Network Security Config доверяет только `src="system"`; обычный пользовательский
  MITM-сертификат PCAPdroid для GHome не подходит.
- Smart Life установлен и авторизован, но EP8 в его аккаунте отсутствует.
- QR-код Tuya IoT Platform предназначен для Smart Life; GHome отвечает
  `please use the designated APP to scan the code to log in`.

## Предпочтительный план продолжения

1. Создать отдельный Android 35 AVD на образе
   `system-images;android-35;google_apis;arm64-v8a`.
2. Запустить AVD и проверить `adb root`.
3. Установить APK GHome из локальной копии (путь к APK не коммитить).
4. Пользователь вручную входит в тот же аккаунт GHome и вводит OTP/пароль.
5. Дождаться синхронизации EP8 в эмуляторе.
6. Получить приватные данные приложения через root либо перехватить вызов
   `DeviceBean.localKey`/`getLocalKey`.
7. Найти запись устройства по `DEVICE_ID` из `.secrets/ep8.env` и извлечь её
   `local_key`.
8. Расшифровать PCAP:

   ```sh
   set -a; source .secrets/ep8.env; set +a
   python3 analyze_tuya_pcap.py \
     '<path-to-pcap>' \
     --local-key "$LOCAL_KEY"
   ```

9. Определить DPS переключателя, направление ON/OFF и остальные доступные
   параметры.
10. Проверить локальное чтение статуса и управление EP8 по
    `$HOST:6668` из `.secrets/ep8.env`.
11. Подготовить конфигурацию Home Assistant LocalTuya или отдельный локальный
    клиент.

## Важные ограничения

- Не сбрасывать и не перепривязывать EP8 до извлечения текущего ключа.
- Повторное сопряжение может изменить `local_key`; новый ключ не расшифрует
  существующий PCAP.
- Не публиковать `local_key`, пароли, OTP, Tuya Access ID и Access Secret,
  а также реальные `device_id`, MAC и LAN IP.
- Не удалять и не заменять GHome на физическом телефоне.

      (`.secrets/ep8.env`).
- [x] `analyze_tuya_pcap.py` расшифровывает запросы и ответы без ошибок padding/JSON.

      (DPS `1`: `true`=ON, `false`=OFF).
- [x] Выполнена успешная локальная команда и подтверждено фактическое переключение
      розетки (TinyTuya на `$HOST:6668`).
- [x] Задокументирована готовая конфигурация локального управления
      (`LOCAL_CONTROL.md`).
